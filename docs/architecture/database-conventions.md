# Convenciones de base de datos (cdr-backend)

PostgreSQL. **Desviación aprobada respecto a la referencia:** el esquema se gestiona con **Flyway**
(la referencia usaba `ddl-auto=update` sin migraciones). Hibernate solo valida (`ddl-auto=validate`).

## 1. Flyway

- Ubicación: `src/main/resources/db/migration/`.
- Nombre: `V{n}__{descripcion_snake}.sql` (doble guion bajo). Ej.: `V1__security_schema.sql`,
  `V2__catalog.sql`, `V3__orders.sql`, `V4__cash.sql`, `V5__seed_roles_parameters.sql`.
- **Una migración aplicada nunca se edita.** Cualquier cambio = nueva migración.
- Datos semilla (roles, parámetros, medios de pago, usuario admin inicial) en migraciones `V*__seed_*.sql`.
  La contraseña del admin inicial **no** va en la migración: se crea en el primer arranque desde `${APP_ADMIN_INITIAL_PASSWORD}`
  (*decisión pendiente de detalle en Etapa 1*).
- Cada entidad JPA nueva ⇒ su migración en el **mismo commit** (skill `backend-entity`).

## 2. Nombres

| Elemento | Convención | Ejemplo |
|---|---|---|
| Esquemas | `security` (tablas de seguridad, como la referencia) y `public` (dominio) | `security.user_app` |
| Tablas | snake_case **plural** (la referencia mezclaba; aquí siempre plural salvo las heredadas de seguridad) | `products`, `order_items`, `cash_movements` |
| Tablas de seguridad heredadas | igual que la referencia | `user_app`, `role`, `permission`, `role_permission`, `user_role`, `refresh_token` |
| Columnas | snake_case (naming físico por defecto de Spring) | `unit_price`, `created_at` |
| FK | `{entidad}_id` (nunca camelCase como `countryId` de la referencia) | `category_id`, `table_marker_id` |
| PK | `id` `INTEGER GENERATED BY DEFAULT AS IDENTITY` (`GenerationType.IDENTITY`) | |
| Índice | `ix_{tabla}_{columnas}` | `ix_orders_status_created_at` |
| Único | `ux_{tabla}_{columnas}` | `ux_products_name` |
| FK constraint | `fk_{tabla}_{referida}` | `fk_order_items_orders` |
| Check | `ck_{tabla}_{regla}` | `ck_orders_total_non_negative` |

## 3. Tipos

| Dato | SQL | Java |
|---|---|---|
| Importe | `NUMERIC(12,2) NOT NULL` | `BigDecimal` |
| Porcentaje | `NUMERIC(5,2)` | `BigDecimal` |
| Cantidad | `INTEGER` | `Integer` |
| Enum | `VARCHAR(30)` + `CHECK (col IN (...))` | enum `@Enumerated(STRING)` |
| Fecha-hora | `TIMESTAMP` (hora local `America/La_Paz`, igual que la referencia) | `LocalDateTime` |
| Imagen | `TEXT` (base64) | `String` |
| Booleano | `BOOLEAN NOT NULL DEFAULT TRUE` | `Boolean` |
| Versión | `BIGINT NOT NULL DEFAULT 0` | `Long` + `@Version` |

Columnas de auditoría (de `Base`) en **todas** las tablas de dominio:
`active BOOLEAN NOT NULL DEFAULT TRUE, created_by VARCHAR(150), updated_by VARCHAR(150), created_at TIMESTAMP, updated_at TIMESTAMP`.

## 4. Integridad

- FKs explícitas con `ON DELETE RESTRICT` (nunca `CASCADE` sobre datos históricos).
- `CHECK` para reglas invariantes: importes ≥ 0, `quantity > 0`, `discount_amount <= subtotal`,
  `total = subtotal - discount_amount`, `(service_type = 'DINE_IN') = (table_marker_id IS NOT NULL)`.
- Índices únicos parciales para reglas de "uno activo":
  - `ux_orders_marker_open ON orders(table_marker_id) WHERE status IN ('PENDING','IN_PREPARATION','READY')`
  - `ux_cash_sessions_user_open ON cash_sessions(user_id) WHERE status = 'OPEN'`
- Unicidad de nombres de catálogo **entre activos**: `ux_products_name ON products(lower(name)) WHERE active`.

## 5. Histórico y borrado

| Tablas | Política |
|---|---|
| `orders`, `order_items`, `order_item_addons`, `order_status_history`, `payments`, `cash_sessions`, `cash_session_summaries`, `cash_movements` | **Nunca** `DELETE`. `cash_movements` y `order_status_history` tampoco `UPDATE` (append-only). |
| `categories`, `products`, `addons`, `table_markers`, `payment_methods`, `parameters`, `user_app` | Borrado lógico (`active = false`). |
| `product_addons`, `role_permission`, `user_role` | Borrado físico permitido (tablas puente sin historia). |

## 6. Índices mínimos previstos

- `orders(status, created_at)` — tablero de cocina y reportes.
- `orders(created_at)`, `orders(created_by)`, `orders(cash_session_id)`.
- `order_items(order_id)`, `order_items(product_id)`, `order_items(category_id)`.
- `payments(order_id)`, `payments(cash_session_id, payment_method_id)`.
- `cash_movements(cash_session_id)`.
- `order_status_history(order_id, changed_at)`.

## 7. Conexión

HikariCP máx. 10 conexiones, `max-lifetime=300000`, `keepalive-time=120000` (igual que la referencia).
Credenciales solo por variables de entorno.
